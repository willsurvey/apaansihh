## LANGKAH 1: SETUP GITHUB REPO

1. Push semua file ke repo GitHub kamu
2. Pastikan repo memiliki permission untuk GitHub Actions:
   Repo → Settings → Actions → General → Allow all actions ✓


## LANGKAH 2: GITHUB SECRETS

Masuk ke: Repo → Settings → Secrets and variables → Actions

### STOCKBIT_BEARER_TOKEN
Token JWT dari stockbit_token.txt (string panjang eyJhbGci...)
Update: setiap 24 jam (token expire), atau setup Playwright refresh

### STOCKBIT_SESSION
Base64 dari stockbit_session.json:

Di terminal:
  base64 -w 0 stockbit_session.json    # Linux
  base64 -i stockbit_session.json      # macOS

Di Python:
  import base64
  data = open("stockbit_session.json", "rb").read()
  print(base64.b64encode(data).decode())

Update: setiap ~30 hari (session expire)


## LANGKAH 3: SETUP VERCEL

1. Import repo dari GitHub ke Vercel
   https://vercel.com/new

2. Framework Preset: Next.js (auto-detect)

3. Set Environment Variables di Vercel Dashboard:
   Project → Settings → Environment Variables

   GITHUB_OWNER         = username GitHub kamu
   GITHUB_REPO          = nama repo ini
   WORKFLOW_FILE        = screener.yml
   GITHUB_TOKEN_WORKFLOW = ghp_xxx... (Personal Access Token)
   CRON_SECRET          = string random untuk keamanan

   ⚠️  PENTING: Gunakan GITHUB_TOKEN_WORKFLOW (bukan GITHUB_TOKEN)
   karena GITHUB_TOKEN sudah direservasi oleh sistem Vercel/GitHub.

4. Buat Personal Access Token (untuk GITHUB_TOKEN_WORKFLOW):
   GitHub → Settings → Developer settings → Personal access tokens → Fine-grained
   Scopes yang diperlukan: Actions (read & write), Contents (read & write)

5. Deploy! Vercel akan otomatis deploy setiap push ke main.


## LANGKAH 4: VERIFIKASI SETUP

## CARA KERJA OTOMATIS

Setiap hari Senin-Jumat jam 18:00 WIB (11:00 UTC):

1. Vercel Cron Job → POST /api/cron
2. /api/cron → trigger GitHub Actions workflow via API
3. GitHub Actions:
   a. Restore stockbit_session.json dari secret STOCKBIT_SESSION
   b. Jalankan screener.py
      → Token dari STOCKBIT_BEARER_TOKEN (env var)
      → Kalau expired → refresh via Playwright headless
      → Kalau gagal → fallback YAHOO_ONLY mode
   c. Simpan hasil ke latest_screening.json + watchlist_YYYYMMDD.json
   d. Commit otomatis ke repo
4. Dashboard di Vercel membaca data dari /api/screening
   (yang proxy ke raw GitHub URL)

## REFRESH TOKEN MANUAL

Di mesin lokal:
  python screener.py    # Test lokal dengan session yang ada

  FORCE_MODE=YAHOO_ONLY python screener.py   # Test tanpa token

Setelah update token, update GitHub Secrets:
  STOCKBIT_BEARER_TOKEN = token baru dari stockbit_token.txt
  STOCKBIT_SESSION      = base64 dari stockbit_session.json (baru)


## TROUBLESHOOTING

### GitHub Actions tidak terpicu dari Vercel:
- Cek env var GITHUB_TOKEN_WORKFLOW sudah diset di Vercel
- Pastikan token punya scope Actions (write)
- Cek log di Vercel: Functions → cron → View logs

### Screening selalu YAHOO_ONLY:
- STOCKBIT_BEARER_TOKEN expired → update secret dengan token baru
- STOCKBIT_SESSION expired → login ulang, base64 ulang, update secret

### Data tidak muncul di dashboard:
- Pastikan GITHUB_OWNER dan GITHUB_REPO benar di Vercel env vars
- Pastikan latest_screening.json ada di repo (GitHub Actions sudah pernah jalan)
- Cek /api/health untuk lihat env vars status

### Build Vercel gagal:
- Pastikan package.json ada dan benar
- Pastikan next.config.js (bukan next_config.js) ada
- Node.js version: minimal 18 (sudah diset di package.json engines)
